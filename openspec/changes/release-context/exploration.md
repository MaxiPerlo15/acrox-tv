## Exploration: Release context — Acrox TV program pages

### Current State
`Alta Data ¡Te Tire!` is a singleton home section at `/#acroxtv`, not a program resource. `StreamingSection` hard-codes its Friday schedule, identity, hosts, CTA, and media component; `AcroxTvMediaSection` always requests one unqualified `/api/acroxtv-feed` response. The only program record, JSON-LD `BroadcastService`, root keywords, feed cache keys, live-refresh window, and navbar live indicator are all Alta Data-specific (`src/domain/home-content.ts`, `src/infrastructure/youtube.client.ts`, `src/components/Navbar.tsx`).

There are no program routes or program sitemap entries. The App Router can use one top-level dynamic filesystem segment as a **static** site capability: the finite local program collection provides `generateStaticParams`, while `dynamicParams = false` makes every unlisted segment a 404. This produces the confirmed direct canonical routes `/alta-data-te-tire` and `/mas-que-nutricion` without a CMS, database, request-time program lookup, or one route file per program. `/proyectos` is protected by an explicit visual lock and is outside this work.

### Affected Areas
- `src/domain/home-content.ts` (or a focused `src/domain/acroxtv-program.ts`) — replace the singleton with the sole typed program registry, `ProgramSlug` union, lookup function, canonical path builder, ordered directory entries, approved editorial/SEO fields, assets, roles, schedule, sponsor associations, CTA context, declared media-source policy, and reserved-slug validation.
- `src/app/[slug]/page.tsx` — add one statically generated top-level program page using `generateStaticParams`, `dynamicParams = false`, `notFound`, and `generateMetadata`; it emits the confirmed direct routes without one-file-per-program duplication.
- `src/components/sections/home/StreamingSection.tsx` and a new program-directory presentation component — change `#acroxtv` from a complete Alta Data surface into an equal-priority directory. Each program card must derive its content and direct link from the registry; home must not embed two competing complete media feeds.
- `src/components/AcroxTvMediaSection.tsx`, `src/components/Navbar.tsx`, and `src/app/globals.css` — move the full media surface to a program page, make CSS program-neutral and route-scoped, and remove the navbar's assumption that one unqualified live result represents all Acrox TV programs.
- `src/domain/acroxtv-feed.ts`, `src/application/acroxtv-feed.client.ts`, `src/app/api/acroxtv-feed/route.ts`, `src/infrastructure/youtube.client.ts`, `src/infrastructure/instagram.client.ts`, `src/infrastructure/swr-cache.ts`, `src/lib/env.ts`, and `.env.example` — validate a program slug at the HTTP boundary, resolve only that program's configured media policy, and key every request/cache/fallback by program. Credentials remain server-only.
- `src/app/layout.tsx`, `src/components/sections/home/HomeJsonLd.tsx`, `src/app/sitemap.ts`, and a program JSON-LD component — remove Alta Data-only root SEO assumptions; produce direct-route page metadata, structured data, and sitemap URLs from the registry.
- `src/components/PrefillContactCta.tsx`, `src/domain/contact-preset.ts`, `src/domain/contact.ts`, and `src/components/ContactForm.tsx` — carry optional, validated program attribution separately from the existing `guest-application` service preset if the contact handoff must identify the program.
- `tests/e2e/{smoke,critical}.spec.ts` and `playwright.config.ts` — add deterministic strict E2E coverage for direct-route generation, metadata/JSON-LD/sitemap, directory navigation, collision protection, program-scoped media fallbacks, contact attribution, accessibility, mobile, and the `/proyectos` lock.
- `public/` — supply approved program identity/OG assets and sponsor assets before rendering those records. The repository has Alta Data assets only; it has no checked-in Más que Nutrición or sponsor assets.

### Approaches
1. **Static direct routes backed by one registry** — create `src/app/[slug]/page.tsx` as a top-level dynamic segment whose known local records are statically generated. The registry derives `/${slug}` for every internal link, canonical, JSON-LD `@id`, sitemap entry, cache key, and test case.
   - Pros: confirmed short canonical URLs, equal top-level program identity, first-class indexable pages, one source of truth, strict unknown-slug 404s, build-time rendering, program-specific SEO/media/sponsor policies, and a compact path for later programs.
   - Cons: the registry must explicitly protect application-owned segments; approved content and asset inputs are still required before both records can ship; provider identifiers and shared-versus-scoped media policy must be confirmed.
   - Effort: Medium.

2. **Duplicate program markup and feed calls** — hand-build one page and one copied home block per program while keeping the current unqualified endpoint and Alta-specific CSS.
   - Pros: superficially small first diff.
   - Cons: cannot safely attribute a shared-channel live stream or episodes, duplicates metadata/JSON-LD/sponsor logic, makes direct canonical URLs and future programs error-prone, and compounds visual regressions. It is not a robust first-class-page architecture.
   - Effort: Low initially, High ongoing.

### Recommendation
Adopt Approach 1. Use `src/app/[slug]/page.tsx` only as an App Router implementation detail; its only generated program pages are `/alta-data-te-tire` and `/mas-que-nutricion`. Do not add a `/programas` namespace, a CMS, database, catch-all/on-demand program route, per-program hard-coded JSX files, redirects from an undeployed namespace, or placeholder editorial claims.

**Registry, URL, and collision contract.** Define a `readonly` tuple with `satisfies` over an explicit `Program` contract, derive `ProgramSlug` from it, and expose `getProgramBySlug` plus `getProgramPath`. `getProgramPath` MUST return `/${slug}`. A record contains only approved facts: immutable `slug`; display/alternate name; route title/description/keywords; identity/card/OG assets; schedule with `America/Argentina/Cordoba`; ordered people and their supplied roles; editorial copy; social links; media policy; sponsor IDs; and CTA context. The canonical slugs are fixed as `alta-data-te-tire` and `mas-que-nutricion`; a display-title rename does not change its slug without an explicit migration decision. The existing `/#acroxtv` remains the Acrox TV directory anchor, not either program's canonical page.

The direct `[slug]` route must coexist with the current explicit top-level routes (`/proyectos`, `/privacy`, and `/terms`) and API namespace. Static App Router routes take precedence, but the program registry MUST still reject every application-owned or future reserved top-level segment, including `api`, so a program can never claim it. Reserve additions must be made with any future direct route before a program uses that segment. The registry must reject duplicate slugs and reserved slugs during construction/build; an unknown non-reserved segment must remain a 404 through `dynamicParams = false`. Do not reserve or add a program route from hypothetical names not supplied as project inputs.

**Home and program composition.** `#acroxtv` becomes a directory with one equivalent card per registry entry: identity asset, approved concise positioning, schedule, people/roles, and a clear direct link to `/${slug}`. It should not load a full player plus three carousels for every program. Each direct program page composes shared shell/navigation, a semantic program hero, approved schedule/people/editorial information, the program-scoped media surface, an optional labeled sponsor area, and the existing guest CTA with program context. Components receive a `Program` object; no page or CSS selector contains Alta Data copy or assumes exactly three feed blocks. New styles must be scoped to `.program-page` and the home directory; do not alter `/proyectos` markup, `projects-*` classes, or unscoped project rules.

**Metadata, JSON-LD, sitemap, and internal links.** The root layout remains organization-wide and drops Alta Data-only keywords/`BroadcastService`. Each static direct program route returns `generateMetadata` from its record: canonical `/${slug}`, approved title/description, Open Graph/Twitter URL and approved image, and `es-AR`. Its JSON-LD emits a `BroadcastService` identified by that direct canonical URL, linked to Acrox's organization, with only the known schedule, names/roles, social URL, image, and language; a `WebPage`/`BreadcrumbList` may reference that same canonical page without duplicating organization claims. The home can expose a `CollectionPage`/`ItemList` with the same direct URLs, not duplicate each page's `BroadcastService`. `sitemap.ts` maps the registry through `getProgramPath` into individual direct URLs. Every program card, CTA that names a program, canonical tag, JSON-LD reference, sitemap entry, live destination, and test fixture must use the path builder; no `/programas/...` strings may be emitted. Local relevance stays factual: Acrox's existing Las Varillas organization/address may be referenced as provider; do not claim that every program is locally produced, covers nearby towns, or provides health outcomes unless approved source content supports it.

**Media and sponsor contract.** Program pages, not the home directory, own rich media. `/api/acroxtv-feed?program={slug}` must reject unknown slugs and return a response for that validated record only. YouTube and Instagram adapters resolve a declared policy: program-scoped sources require a confirmed program playlist/account and program-prefixed cache keys; an explicitly approved shared source may be shown as shared Acrox TV content, never mislabeled as that program's episodes or live broadcast. The current channel-wide live discovery cannot be assigned to either page without a reliable program discriminator, so the safe default is an unavailable/live fallback. The navbar may display a live state only when an aggregate endpoint can return an attributable **direct program URL**; otherwise it links to `/#acroxtv` without a false live badge.

Sponsors are display data, not a sales package: an approved sponsor record contains a name, licensed logo asset, optional destination URL, disclosure/mention copy, and explicit program associations. Render sponsors on the associated program page after the core program information and before/alongside the program CTA only when the complete record exists. A home-card sponsor marker is optional and must be driven by an explicit approved placement; do not repeat sponsor logos across the directory by default or imply endorsement, especially for health-related content.

**First slice and test implications.** First establish the registry, direct static routes, equal-priority directory, direct-route metadata/JSON-LD/sitemap, program-neutral composition, and red-first Playwright tests. It may use safe empty-media fallbacks; it must not wire Más que Nutrición to Alta Data's playlist or Instagram feed. Tests must first prove that both exact canonical paths render, home cards navigate to those paths, metadata/JSON-LD/sitemap use only the direct URLs, and unknown or reserved program candidates cannot resolve as program pages. Existing `/proyectos`, `/privacy`, `/terms`, API behavior, responsive navigation, and the `/proyectos` visual lock remain non-regression coverage. Since the prior segmented namespace is not an existing route, tests should assert the release emits no `/programas/...` internal links or sitemap/canonical values rather than inventing a redirect requirement.

The vertical slice cannot launch both equal program cards/pages without: approved Más que Nutrición logo/card/OG assets; approved route/card/editorial copy and role wording; confirmed YouTube playlist plus live attribution rule per program; confirmed Instagram policy/account(s); and approved sponsor names, associations, assets, links, and disclosure copy. Add provider wiring, per-program cache behavior, and sponsor rendering only once those inputs exist.

### Risks
- A top-level dynamic segment can shadow future direct-page intent if its reserved-slug policy is not maintained. The registry validation, static-route precedence, and collision tests are required to keep application routes distinct from program URLs.
- The current YouTube live search is channel-wide and its Friday Córdoba refresh window is hard-coded. Reusing it would publish the wrong program's live state; schedule windows and cache keys must be program data and independently tested.
- The existing Instagram credentials identify one account. A second program needs a confirmed scoped account or an explicit shared-content policy; no source exists to infer either.
- Más que Nutrición's logo, OG/card imagery, full approved copy, media identifiers, sponsor roster/assets/licenses, and health-content review language are absent. Do not fabricate them, use Alta Data assets, or make diagnostic/therapeutic claims.
- `Navbar` and the home media component currently fetch the singleton feed, while CSS contains Alta Data names and `#acroxtv` nth-child assumptions. A partial extraction can regress performance, mobile layout, keyboard player behavior, or falsely label live content.
- Strict TDD is configured but Playwright is the only test layer. Tests must be written before the behavior and provider calls must be stubbed per slug; dependencies were unavailable in the prior exploration checkout, so the suite still requires execution in an installed environment.
- `/proyectos` has a visual lock. Scope all new CSS and retain its current markup/classes; execute its locked smoke/visual viewport checks as a non-regression gate.

### Ready for Proposal
Yes — propose the static registry-backed direct program-page architecture, with the prerequisite inputs and two delivery slices explicit: (1) static directory/pages, direct-route SEO/JSON-LD/sitemap, reserved-slug protection, safe media fallbacks, and strict E2E; (2) confirmed program media integrations and sponsor display. The earlier home-only recommendation is superseded: complete program surfaces belong on first-class direct public pages, while home is the equal-priority directory. `/proyectos` remains untouched and visually locked.
