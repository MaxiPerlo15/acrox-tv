# Aggregate GA4 contact-form funnel

## Goal
Measure how many consented visitors start editing the contact form, make invalid submission attempts and reach the existing valid WhatsApp handoff attempt—without recording names, message text, field values, error details, selected service or any other personal data.

## Authorized boundary
- User accepted adding this aggregate funnel after the GA4 production release at `main` commit `9efb5b6fe0b79c087009a46ff1a84177c351a6c2`.
- User's earlier restriction still forbids new worktrees, generated E2E/build/typecheck artifacts and publication of unrelated dirty `develop` program work. The user subsequently authorized commit, merge and push of the isolated funnel into `main`. Do not check out or commit dirty develop.
- Analytics remains strictly opt-in. Never add form values, field identifiers, validation messages, service selection, WhatsApp URL, names or free text to GA. An attempted handoff is not a sent WhatsApp message. Do not duplicate the existing valid `click_enviar_whatsapp` event.
- Distinct custom event names `contact_form_start` and `contact_form_invalid_submit` avoid a collision with GA4 Enhanced Measurement's `form_start` and `form_submit`. Those automatic Google property settings remain external/unverified.

## Semantics
- Start: first user-driven edit through `updateForm` per mounted form; no focus-only, preset-driven, or retroactive events. A new mount can start again. The start latch does not reset after successful submission.
- Invalid attempt: once per unlocked invalid submit, after validation. Repeat attempts count separately; blur/change validation does not count.
- Valid attempt: the existing `click_enviar_whatsapp` after validation and WhatsApp URL construction, before opening WhatsApp. It neither proves a message was sent nor identifies a person.
- Withdrawal while Google's script is pending must purge queued new custom events as well as existing event names.
